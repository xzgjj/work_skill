# 工作流细则（同源于 审查配合方案.md）

## 两道门
- **技术门**（`rg gate`，自动）：静态检查 + 最小测试 + 文档漂移映射；任一失败 → 非零退出 + 「待返工」标记（fail-closed）；
- **审批门**（用户，人工）：证据链确认 →（按需）审计 → 放行/打回 → consent 记录。用户权限 > 门禁（override 需记录）。

## 回合粒度
- 一次生成 ≤1000 行（默认 300–600），3–5 回合 = 一小阶段；修改/调试不计回合；
- 每功能：用例先行（TDD 红）→ 实现（绿）→ 最小测试跑通为止 → git commit（feat:/fix:/test:/docs:/chore:）；
- 常规回合连续推进（不逐回合等待）；`waiting-user` 仅用于审计回合/用户主动暂停/阶段收口。

## 每阶段结束（顺序固定）
全量测试绿（TDD 配合）→ 全面审计（按需；回合内为聚焦审计）→ 修改闭环 → review ≥3 轮全通过 → problems 等价 0 错 → 更新重要文档 → 阶段总结 → 用户 review → **git（合并/开下一整数分支）需用户同意**；最终阶段 git 同需同意。

## 分支与 git 纪律
整数分支 1,2,3… 从 main 派生；一阶段一分支；功能 commit 自动；**合并 = consent 后**；禁直改 main；漂移单（文档≠代码）→ 用户裁决改码/改文档。
